# Suspicious code

Some code is written to be hard to read, to do more than it says, or to make a reviewer (a person or an AI) look away. wpantry reads the repos' own source and, on a machine scan, every editor extension, agent plugin and browser extension installed, for the shapes those take. None of them is wrong on its own, so the verdict depends on where the pattern sits: what is routine in one language or place is out of place in another. A finding **fails** where it is out of place, **warns** elsewhere, and a policy file can turn any id or path into a warning for good. Nothing is ever silenced.

| Id | What | Fails when | Warns when |
|---|---|---|---|
| `EXEC-DECODED` | `eval`, `new Function`, `setTimeout("…")`, `exec`/`compile` with a decoder (`atob`, `fromCharCode`, `b64decode`, `marshal.loads`, escapes) within a few lines of it | always (JS, TS, HTML, Python, Ruby, PHP) | — |
| `ENCODED-PAYLOAD` | An array of 32 or more hex, binary or byte literals | beside `EXEC-DECODED` | in a web script or Python, with or without code that turns numbers into text near it. Never in C, Rust, Swift, shaders, CSS, or paths that hold tables (`vector`, `fixture`, `wasm`, `shader`, `kernel`, `gpu`, `font`, `codec`, `table`, `lut`, `crc`, `sha`, `aes`, `dist`, `build`) |
| `STRING-DECODER` | `charCodeAt` and `fromCharCode` with XOR, shifts or modulo in one file | beside `EXEC-DECODED` | alone (hashing and base64 libraries look like this) |
| `ESCAPED-SOURCE` | A run of 30 or more `\x`/`\u` escapes | beside `eval` | alone; never in table paths |
| `PRIV-ESCALATION` | `curl … \| sh`, `sudo`, setuid bits, sudoers, `authorized_keys`, launch agents and daemons, cron, services, run keys, Gatekeeper and SIP off, quarantine stripped. Only in files that run commands: shell scripts, CI workflows and Dockerfiles, manifests, JavaScript, Python or native code that spawns processes (`child_process`, `subprocess`, `system(`), and installed code. Website copy or a string table that says "run sudo …" runs nothing and is not read for this | in package.json and other manifests; in a JavaScript, Python or native file that itself runs commands; in installed code: for `curl \| sh`, setuid, sudoers, launch daemons, SIP and Gatekeeper, quarantine, run keys | in shell scripts and workflows (installers use sudo), in tests, and for a bare `sudo`, a launch agent, cron or a service |
| `CREDENTIAL-ACCESS` | A JavaScript, Python or shell file that reads ssh keys, cloud and registry credentials; Safari's cookies, autofill, history and internet passwords (`find-internet-password`, `dump-keychain`); the Chromium family's (Chrome, Opera, Opera GX, Brave, Edge, Vivaldi, Arc, Chromium) `Login Data`, `Login Data For Account`, `Web Data`, `Local State` and `Network/Cookies`, and its `<Browser> Safe Storage` keychain item, including `find-generic-password -wa Chrome` (the AMOS pattern); Firefox's `logins.json`, `key4.db` and `cookies.sqlite`; password managers (1Password and its `op` CLI, LastPass, Bitwarden and `bw`, KeePass and KeePassXC, Dashlane, Proton Pass, Enpass, NordPass, Keeper, `pass` and `gopass`; an extension's id counts only beside the path of an extension's storage, since password managers list each other's ids); the GNOME keyring, KWallet and `secret-tool`; extension storage (wallet keys), the keychain, wallet files | in JavaScript or Python with network code in the same file, or in installed code | read only, in shell scripts, in tests |
| `WALLET-SIGNING` | `signTypedData`, `personal_sign`, `eth_sendTransaction`, `setApprovalForAll`, `increaseAllowance`, `permit`, `signMessage`, `signAllTransactions`, `signAuthEntry`, `submitAndWait`, `tron_requestAccounts`, `trx.sign`, … with a wallet provider or library in reach: Ethereum and the EVM chains (BSC, Polygon, Tempo), Solana, Stellar, the XRP Ledger, Tron | with an unlimited allowance (`MaxUint256`); with an operation that hands the account itself over rather than spending from it (Tron `updateAccountPermissions` / `AccountPermissionUpdateContract`, XRP `SetRegularKey`, `SignerListSet`, `asfDisableMaster`, `AccountDelete`, Stellar `masterWeight` and `accountMerge`, Solana `AuthorityType.AccountOwner`, `createSetAuthorityInstruction`, `SystemProgram.assign`, EVM `signAuthorization` (EIP-7702), Tempo `accessKey.authorize` and the Account Keychain precompile), also in Python with a chain library; with valid addresses of two or more chains hardcoded beside the signing (a dapp has one treasury; a drainer has a wallet per chain); in obfuscated code; or in installed code (an extension or plugin asking your wallet to sign) | in the project's own code: that is what a dapp does. One chain's address hardcoded is named, not failed |
| `CLIPBOARD-SWAP` | A clipboard read (`navigator.clipboard.readText`, `pbpaste`, `NSPasteboard`, `pyperclip`, `GetClipboardData`, `xclip -o`, `wl-paste`, `clipboard.ReadAll`, `Clipboard.GetText`, …) with wallet addresses in hand: valid addresses hardcoded (checked by checksum, so a 34-character word counts only when it is one) or the regular expressions that recognise them (`[a-fA-F0-9]{40}`, `[a-km-zA-HJ-NP-Z1-9]{25,34}`, `[A-Z2-7]{55}`, …). Read in JavaScript, Python, shell, C-family, Go, Rust, C# and installed code | with a clipboard write beside the read (`writeText`, `pbcopy`, `pyperclip.copy`, `SetClipboardData`, `xclip -i`, `set the clipboard to`, …): a clipper swaps the address you copied for its own; a read with addresses in installed code | a read with address patterns and no write (a form validating what was pasted), or in a test. A write alone is a "copy address" button and isn't reported |
| `THIRD-PARTY-SCRIPT` | `<script src="https://…">` without `integrity=` | over plain http, or on a project that asks wallets to sign (the supply-chain drainer: the script decides what gets signed) | otherwise |
| `RAW-IP` | `http://1.2.3.4`, `ws://…` to a bare address | beside another failing finding | alone |
| `TYPOSQUAT` | A locked dependency one keystroke from a popular package of its ecosystem (`lodahs`, `reqeusts`, `lodesh`, `@babe1/core`), against the bundled list in `assets/defaults/popular.txt`: the most downloaded names of npm, PyPI, crates.io and RubyGems, regenerated by `scripts/popular.py`. A listed name is never a squat, names under four characters are skipped, and a name its registry reads as the same as a listed one (separators dropped, swapped or doubled: `nodefetch`, `python_dateutil`, `serde-json`) is the listed, older package, since npm refuses such a name and crates.io and PyPI equate them. A separator in place of a letter (`xml-js`, `xml2js`) is a different word, not a slip | the popular package is in the same lockfile too (a typo that pulled in a stranger's package beside the one meant) | otherwise |
| `BINARY-BLOB` | Prebuilt `.node`, `.wasm`, `.so`, `.dylib`, `.dll` or `.exe` files a dependency ships (`node_modules/*`, including `build/` and `prebuilds/`) or the repo commits, with nothing to build them from (no `binding.gyp`, `Cargo.toml`, C, Rust, Zig or WAT sources beside them). Well-known native publishers (esbuild, sharp, swc, Prisma, sqlite, …) are skipped | a file named like a binary whose first bytes aren't an executable or WebAssembly header: a payload wearing a binary's name | otherwise |
| `PROFILING-PROMPT` | A prompt or agent instruction that tells an AI to build a profile of a person from their collected data and rank what they own to monetize it. It fires only where several families co-occur in one block: a role or sole-source "evidence bundle" framing, fields that mine identity (emails, domains, search history, a school LMS, an employer, hobbies, saved passwords), and an explicit monetization ranking. An ordinary OSINT note or marketing deck trips none of them together | in prompt and agent files (`.md`, `.mdc`, `.cursorrules`, MCP and agent configs, `AGENTS`/`CLAUDE` files), and in installed code, where such a prompt is loaded and obeyed | elsewhere |
| `CARDHOLDER-DATA` | A primary account number (PAN) that passes the Luhn check and matches a known issuer (Visa, Mastercard, Amex, Discover), separators tolerated, in source, `.env`, JSON/CSV/log files; or code that collects card fields (`card_number`, `cvv`, `pan`, …) and sends them on. The published test numbers (the `4111 1111 1111 1111` family, `4242…`) and anything under a test or fixture path are named, never failed. PCI DSS forbids storing a PAN in the clear and keeping a CVV at all | a PAN beside a CVV or card field, or in a file that also sends data; code that collects card fields and sends them | a lone PAN; a test number |
| `WEAK-PASSWORD` | A `password`/`passwd`/`pwd`/`secret` assignment whose value is a known-weak password, from the bundled two-tier `assets/defaults/weak-passwords.txt`. Defaults and throwaways (`password`, `admin`, `changeme`, `letmein`, …) fail; common dictionary passwords (`monkey`, `dragon`, `sunshine`, …) only warn. The value is normalized first (trailing digits and symbols dropped, leet undone) so `Admin1` and `p@ssw0rd` match too. Provider tokens and high-entropy secrets stay with the gitleaks secret scan; this is the source-level, non-git part | the value is a known default or throwaway password (fail tier) | a common dictionary password (warn tier), or any other non-weak hardcoded literal (a config default); never for placeholders (`${VAR}`, `<…>`, env lookups, `xxx`), tests or fixtures |
| `KEYLOGGER` | Code that installs a global keyboard hook or reads raw keystrokes: a macOS event tap on key-down, a Windows low-level keyboard hook, a polled key-state loop, the Linux raw input event device, an X11 record tap, or a Python/Node keystroke library | in installed code, or when the same file also writes the keys to a file or sends them over the network | in a repo's own source (an accessibility tool, hotkey daemon or game may do it); never in tests |

`TYPOSQUAT` reads the lockfiles, not the source, so it runs with the dependency checks and names the lockfile; a package you do mean to use goes in the policy by id or by `path:` of the lockfile. `BINARY-BLOB` is why the JFrog "testmetest" repos worked: a `.node` addon with a `postinstall` to load it. The repo-hook check fails that pairing outright; this one warns about every prebuilt binary a dependency asks you to trust, so the pairing is never the first you hear of it.

The reasoning behind "out of place": a hex table in a Metal kernel, a CRC file or a CSS colour is the normal way to write it; the same bytes in a page's script next to `fromCharCode` are a payload. `sudo` in `install.sh` is how installers work; `sudo` in an npm `postinstall` is how a worm gets root. A dapp asks a wallet to sign; a dependency, a browser extension or an obfuscated bundle asking a wallet to approve an unlimited allowance is a drainer. A wallet app sets its own account's options; a page that sets your Tron permissions, your XRP regular key or your Stellar master weight takes the account, which is why those fail wherever they sit. The addresses are recognised by checksum ([`addresses.rs`](../../rust/crates/wpantry/src/addresses.rs)): Base58Check for Bitcoin, Litecoin, Dogecoin and Tron, Ripple's alphabet for XRP, bech32 and bech32m, Stellar's StrKey CRC, 32 bytes of Base58 for Solana, and `0x` with 40 hex digits for every EVM chain, so an identifier or a hash is never mistaken for one. The same recogniser is behind the machine scan's clipper check ([checks-and-sources.md](checks-and-sources.md)).

## Installed code

On a machine scan the same rules run over the directories of every VS Code-family editor's extensions, every agent harness's plugins, and every Chromium-family browser's extensions, as **installed** code: there, reading a credential store or asking a wallet to sign fails outright, because the project's own intent isn't a defence for code that arrived through a marketplace.

## The policy file

`--suspect-policy FILE` (default: the bundled, empty list) holds one entry per line: an id (`PRIV-ESCALATION` or `SUSPECT-PRIV-ESCALATION`) or `path:<text>` matched against the file's path inside the repo (`path:scripts/legacy/`). A finding that matches warns instead of failing and says so. There is no way to drop one: a reviewer should still see it.

## What it is not

A verdict. The rules find the shapes of attacks, including in honest code that happens to share one; they miss attacks written without them. Read what the finding points at. Built output (`dist`, `build`, `out`, `_site`, `.next`) is skipped in a repo and read as installed code elsewhere; minified bundles are read (a drainer ships minified), which is why `ENCODED-PAYLOAD` alone never fails and `EXEC-DECODED` needs the decoder beside the call.

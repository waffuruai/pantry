# What wpantry checks, and where the answers come from

wpantry inventories what is installed on your computer and what your git repos lock, then asks a few public sources only about those exact versions. This page lists every check and every source. For running it, see [usage.md](usage.md); for installing it, [install.md](install.md); for how the scanner is put together, [architecture.md](../architecture.md).

## What it checks

| Area | What |
|---|---|
| Malware | YARA rules over the files malware lands in: the top two levels of Downloads, Desktop and the temp directories, the programs launch items and autostart entries start, and the executables in your repos; `--deep` reads all of `~` with every system's rules. The rules are ours (built in) and [YARA Forge](https://github.com/YARAHQ/yara-forge)'s `full` package, about 12,000 rules from 40+ projects, fetched to your machine; only this system's and any system's are used by default. A malware hit fails, Critical; a hacking tool or unwanted program warns, High; a heuristic warns. Each file's result is cached until it or the rules change. The engine is [wpantry-yara](../../rust/crates/wpantry-yara), written here; [malware-rules.md](malware-rules.md) says which rules and how to add your own |
| Your repos' dependencies | The lockfiles in every git repo it finds: Cargo, npm, pnpm, yarn, bun, deno, Swift, Go, uv, poetry, pip, Pipenv, Bundler, Composer, Maven, Gradle, NuGet, Pub, Hex, Conan |
| Committed secrets | Each repo's whole git history once, then only the commits its branches gained since, with [gitleaks](https://github.com/gitleaks/gitleaks); secrets are never printed or stored, only the rule, file, line and commit. A repo's own `.gitleaks.toml` is reported, not obeyed; its `.gitleaksignore` is |
| Malicious packages | Every package name against the OpenSSF malicious-packages index; VS Code's malicious-extension list |
| AI harnesses | The MCP servers your repos and coding agents (Claude Code, Codex, Cursor, Gemini CLI and others) start (an unpinned `npx some-server` warns: it runs whatever is latest), their plugins, skills and bundled npm packages |
| Install scripts | Dependencies that run code when installed, outside an allowlist |
| Suspicious code | Strings decoded at run time and fed to `eval`, payloads kept as arrays of numbers, hand-rolled decoders, source written as escapes; `sudo`, setuid, `curl \| sh` and persistence in files that run commands; credential stores read and sent (ssh and cloud keys, Safari, every Chromium browser's files and its keychain Safe Storage key, Firefox, password managers, the Linux keyrings); code asking a crypto wallet to sign or approve, or to hand the account over (EVM and Tempo key authorizations, Solana authorities, Stellar master weight, XRP regular keys, Tron permissions); clippers that read the clipboard and write a wallet address back; pages loading third-party scripts without an integrity hash; traffic to bare IP addresses; dependencies one keystroke from one of the most downloaded packages of their registry and not themselves among them; prebuilt binaries with no source; AI prompts that profile a person to rank their assets for monetization; card numbers and fields in the clear (PCI DSS); hardcoded and weak passwords; keystroke loggers. In the repos, and on a machine scan in every editor, agent and browser extension installed ([suspect-code.md](suspect-code.md)) |
| Programs listening with MPTCP on | A Go module whose `go` line is 1.24 or newer and whose source listens for TCP (`net.Listen`, `ListenConfig`, `http.ListenAndServe`, gRPC, fasthttp) without opting out (`SetMultipathTCP(false)`, `godebug multipathtcp=0` in `go.mod`, a `//go:debug` directive, or `GODEBUG=multipathtcp=0` in a Dockerfile, compose file, Kubernetes manifest, systemd unit or `.env`), and any source that asks for MPTCP by name (`IPPROTO_MPTCP`, socket2's `Protocol::MPTCP`, `SetMultipathTCP(true)`): Go 1.24 listens with Multipath TCP on Linux by default, which reaches [CVE-2026-98432](https://osv.dev/vulnerability/CVE-2026-98432) through the program, not only the kernel. A `project` warning (Critical, `fixed` empty, counted as unfixed) with the opt-out as the step, until the kernel under it is fixed |
| Hidden text | Unicode that reads one way and runs another (bidi overrides, Trojan Source), invisible tag and zero-width characters that smuggle instructions to an AI assistant, identifiers mixing scripts, and identifiers packed with weapon and poison vocabulary so an AI reviewer refuses to read the code (`AI-BAIT`, terms in `rust/crates/wpantry/assets/defaults/bait.toml`) |
| Documents and images | PDFs (JavaScript on open, `/Launch`, hex-escaped names, embedded files, data after `%%EOF`), Office files (macros where the format shouldn't have them, Excel 4.0 macro sheets, templates and objects fetched from a URL on open, DDE fields, OLE objects), RTF objects, images that are really programs or carry one after their last byte, SVGs with scripts, and [ClamAV](https://www.clamav.net/) over all of them when it is installed. In the repos, and on a machine scan the top of `~/Downloads`, `~/Desktop` and `~/Documents` ([documents.md](documents.md)) |
| Repo hooks | Code a repo runs the moment it is opened or installed: Claude Code and Gemini hooks, MCP servers kept in the repo, VS Code tasks on folder open, devcontainer commands, direnv, the repo's own install scripts, gyp expansions, native addons; plus the file names, packages, hosts and hashes of known hijacked-repo campaigns. A hook you have read goes in `--hooks-policy FILE` (the warning prints the line) and is counted, not listed, until its command changes; a hook that fails is never accepted |
| Licenses | With `--licenses`, dependency licenses outside an allowlist |
| Container images | The images your repos build from |
| The OS | Debian, Ubuntu, Alpine, SUSE packages (from the package database), dnf distros, Arch; macOS Software Update |
| Installed software | Runtimes and compilers (every version a version manager keeps, not just PATH), package managers, CLI tools, datastores, Docker, global pip/npm/gem/cargo/pipx packages, Homebrew formulae (`brew vulns`), apps, browsers, Electron apps, editor extensions; mise itself against OSV and its latest release |
| Homebrew without `brew` | Bottles poured into the Cellar by mise's `brew:` engine (no `brew` command, so no `brew vulns`): each formula the tool catalog knows is checked against OSV and endoflife.date; the rest are reported "not checked" |
| End of life | Runtimes and datastores past their end-of-life date fail |
| Certificate authorities | System, OpenSSL, Homebrew, certifi, pip and Node trust stores against the leaked eMudhra CAs (`wpantry harden ca-trust` distrusts them until the OS update ships) |
| Clipboard clippers | A valid address of each shape a clipper goes after (EVM, Bitcoin, Tron, Solana, XRP, Stellar) copied to the clipboard and read back twice; one that comes back as a different address is a clipper at work (`CLIPPER-ACTIVE`). The clipboard is put back; an image or files on it are left alone and the test says it was skipped. Every launch agent and daemon, autostart entry and user service is read for the program it runs: one that touches the clipboard and carries wallet addresses or the patterns that recognise them fails (`CLIPPER-PERSISTENCE`), one that touches the clipboard from a temporary or hidden place warns. A browser extension whose manifest asks for both `clipboardRead` and `clipboardWrite` warns (`CLIPPER-EXTENSION`), and fails when its code has the clipper shape (`SUSPECT-CLIPBOARD-SWAP`). `--no-clipboard` skips the copy, never the reading. A clipper that only wakes for a real wallet, or an extension that swaps on paste, shows itself while you work: `wpantry clipboard --watch` reads the clipboard four times a second, never writes it, and alerts (a line, a desktop notification, a `clipper` event in the cache) when a copied address becomes a different address of the same chain within two seconds; `wpantry schedule install --clipboard-guard` keeps it running from login ([usage.md](usage.md#guarding-the-clipboard)) |
| The machine's settings | FileVault or LUKS, the firewall and its logging, Gatekeeper, SIP and Secure Boot, automatic updates and time sync, Remote Login, AirDrop and the sharing services, guest and automatic login, an everyday account that isn't an administrator, the screen lock, XProtect and XProtect Remediator, whether DNS leaves the machine encrypted (DoT or DoH; plain DNS to an internal resolver only warns), and more ([posture.md](posture.md)); `--no-posture` skips them |
| Persistence | Every place a program can come back from after a reboot: launch agents and daemons, the login items and agents apps carry, cron, at, periodic, emond, authorization plugins, kernel and system extensions, Quick Look and Spotlight plugins, the shells' startup files and `DYLD_INSERT_LIBRARIES` on macOS; systemd units, cron, at, XDG autostart, the startup files and `/etc/ld.so.preload` on Linux. Compared with the last scan's list in the cache: a new item warns (`PERSISTENCE-NEW`); library injection, a persisted program whose signature no longer verifies, and one in a temporary or hidden place warn every scan. Each program's `codesign` verdict and quarantine attribute go in the note ([posture.md](posture.md#persistence)) |
| Developer-tool guardrails | Editor extensions wait 72 hours before a new version installs (`wpantry harden extension-cooldown`), git hooks that check commits |

`--no-machine` limits a run to the repo rows (dependencies, secrets, malicious packages, harnesses, install scripts, suspicious code, programs listening with MPTCP on, hidden text, documents and images, repo hooks, licenses, images). What a run could not check shows up as "not checked", never as clean.

A finding fails when something here has a known vulnerability with a released fix, is past end of life, is a known malicious package, is a committed secret from a provider-specific rule, is a clipper or a clipper's swap, or is a Critical or High posture setting. It warns when there is no fix yet, an app is outdated, an MCP server is unpinned, an install script runs, a generic secret rule matched, a Medium or Low posture setting is off, or a persistence item is new, injects a library, has a broken signature or runs from a hidden place.

## Sources

These are the only hosts the binary will connect to: every source is declared in one file compiled into the binary ([`sources.toml`](../../rust/crates/wpantry/assets/defaults/sources.toml): its URL, how often it is fetched, how much of it is read, its licence and what a request sends), the host list (`net::HOSTS`) is that file's hosts, any other URL is refused before a connection is made, a redirect is followed only to a host on the list (and an `Authorization` header never follows it off the first host), and a test checks every source against it. Every request is https, verified against your machine's own trust store (so a certificate authority you distrust is distrusted here too), names wpantry in its User-Agent, times out after 30 seconds, and goes through `HTTPS_PROXY` when it is set. Answers are cached in `~/.cache/wpantry/wpantry.db` for a day; `--offline` uses only the cache, and a source that can't be reached and has nothing cached is reported "not checked".

| Source | Answers | What is sent |
|---|---|---|
| [OSV.dev](https://osv.dev) (`api.osv.dev`) | Known vulnerabilities, affected and fixed versions, severity, aliases, for every ecosystem OSV covers (crates.io, npm, PyPI, Go, RubyGems, Maven, Debian, Ubuntu, Alpine, SUSE, and more) | The (ecosystem, name, version) of what is installed or locked. No file contents, paths or secrets. Workspace members and local packages are not sent |
| [CISA Known Exploited Vulnerabilities](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) | The `KEV` mark: vulnerabilities seen exploited in the wild, which the report puts first | Nothing; the catalog is downloaded |
| [endoflife.date](https://endoflife.date) | End-of-life dates for runtimes and datastores | The product name |
| [OpenSSF malicious-packages](https://github.com/ossf/malicious-packages) | Known malicious package names, per ecosystem | Nothing; the index is cloned with git |
| [deps.dev](https://deps.dev) | Dependency licenses, with `--licenses` | The (ecosystem, name, version) of your repos' dependencies |
| [Homebrew](https://brew.sh) (`formulae.brew.sh`, `brew vulns`) | The cask catalog, to find outdated apps; `brew vulns` for installed formulae | Nothing; the catalog is downloaded and `brew` runs locally |
| [Arch Linux security tracker](https://security.archlinux.org) | Advisories for Arch packages | Nothing; the tracker is downloaded |
| Chrome and Firefox release feeds (`versionhistory.googleapis.com`, `product-details.mozilla.org`) | The current browser versions | The platform |
| [PostgreSQL security page](https://www.postgresql.org/support/security/) | Fixed PostgreSQL releases | Nothing; the page is downloaded |
| VS Code Marketplace and [Open VSX](https://open-vsx.org) | Editor extension versions, and VS Code's list of malicious extensions | The extension ids |
| GitHub releases (`api.github.com`) | The latest release of tools without a feed (mise); `GITHUB_TOKEN` lifts the anonymous rate limit | The repository name |
| [signature-base](https://github.com/Neo23x0/signature-base) IOC lists (`api.github.com`) and [abuse.ch Feodo Tracker](https://feodotracker.abuse.ch) (`feodotracker.abuse.ch`) | Known-bad file hashes, file names malware uses, and command-and-control hosts, for the malware scan; daily | Nothing; the lists are downloaded |
| [YARAify](https://yaraify.abuse.ch) (`yaraify-api.abuse.ch`), [CIRCL hashlookup](https://hashlookup.circl.lu) (`hashlookup.circl.lu`) and, with your `ABUSECH_AUTH_KEY`, [MalwareBazaar](https://bazaar.abuse.ch) (`mb-api.abuse.ch`) | Whether a file the malware scan flagged is known malware (and which family) or known-good software | The flagged file's SHA-256 only, never the file, its name or path, only after you say yes once, at most 50 a scan; `--no-online-hash` never sends it |
| [YARA Forge](https://github.com/YARAHQ/yara-forge) releases (`api.github.com`, then `release-assets.githubusercontent.com` or `objects.githubusercontent.com`, where GitHub redirects the download) | The malware scan's community rules, at most daily | Nothing; the package is downloaded |
| [Have I Been Pwned](https://haveibeenpwned.com) or [XposedOrNot](https://xposedornot.com) | Whether an email address appears in a breach | Your email address, only after `wpantry breach --enable` and only after you say yes; `HIBP_API_KEY` selects Have I Been Pwned |

**Your own sources.** `wpantry sources` lists every source, when it was last fetched and what last went wrong. A file of your own, `~/.config/wpantry/sources.toml` (or `--sources FILE`), can turn a source off (`tier = "off"`) and add YARA rules, hash, host and file-name lists, an OSV-compatible API, or a hash lookup, in the same format as the bundled file. A source of yours on a host wpantry doesn't already ask, or one that sends anything (a hash lookup may send a flagged file's SHA-256 and nothing else), is used only after you say yes, once; with `--no-input` and no yes it is reported not checked. [The sources file](../../specs/design/sources-file.md) has the details.

Local tools run on your machine and send nothing: [gitleaks](https://github.com/gitleaks/gitleaks) for secrets, `git`, `openssl` for the trust stores, [ClamAV](https://www.clamav.net/) over documents and images when it is installed, `brew` and `docker` (or podman) when present, and the OS's own package database and `softwareupdate`. `wpantry tools` lists them and which are missing.

The posture checks follow the [CIS Benchmarks](https://www.cisecurity.org/cis-benchmarks) for macOS and Linux and read settings locally ([posture.md](posture.md)). The certificate-authority check follows the [eMudhra advisory](https://emudhra.we-have-a-problem.com/). The lockfile readers and the OS package-database mapping were written against [osv-scanner](https://github.com/google/osv-scanner) and [osv-scalibr](https://github.com/google/osv-scalibr)'s test fixtures, so a lockfile reads the same way here as there. The projects and data this stands on are credited in the README's [acknowledgements](../../README.md#acknowledgements).

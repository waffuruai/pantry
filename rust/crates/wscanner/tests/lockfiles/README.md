# Lockfile golden files

Each directory holds one lockfile and `expected.txt`, the `ecosystem name version` lines its
extractor must return (sorted). The lockfiles were generated by the real tools, and each
`expected.txt` comes from that tool's own view of the result, not from our parser. Where the
tool's view includes something the extractor deliberately leaves out (a local or path
package, a private recipe), the table says what was dropped:

| Case | Lockfile made with | Expected from |
|---|---|---|
| `cargo-v4` | `cargo generate-lockfile` (registry, path and git dependencies) | `cargo metadata`, crates.io sources |
| `cargo-workspace` | this workspace's own `Cargo.lock` | `cargo metadata`, crates.io sources |
| `npm-v3`, `npm-v1` | `npm install --package-lock-only` (npm 10, `--lockfile-version 1` for v1) | `npm ls --all --json` |
| `pnpm-v9`, `pnpm-v6` | `pnpm install --lockfile-only` (pnpm 10, pnpm 8) | `pnpm list --depth Infinity --json` |
| `go` | `go mod tidy` (Go 1.24) with `replace` and `toolchain` directives | `go mod edit -json`, replaces applied, `toolchain` as `stdlib` |
| `uv` | `uv lock` (uv 0.11) with an editable project | `uv export --all-groups --no-emit-project` |
| `swift-v1`, `swift-v2` | written by hand in SwiftPM's formats (no Swift toolchain here) | by hand |
| `requirements` | `uv pip compile --generate-hashes` (uv 0.11) for `requirements.txt` and the dev pins; `requirements-dev.txt` starts with `-r requirements.txt` | `pip install --dry-run --no-deps --report` (pip 26) on `requirements-dev.txt`, names PEP 503-normalized |
| `yarn-v1` | `yarn install` (Yarn 1.22) with an `npm:` alias and a `file:` dependency | `yarn list --json`, the alias read as its package, the `file:` package dropped |
| `yarn-berry` | `yarn install` and `yarn add` (Yarn 4.18, lockfile v10): an alias, a `file:` dependency, the built-in typescript `patch:` | `yarn info --all --recursive --json`, `npm:` and `patch:` entries |
| `bun` | `bun install` (Bun 1.4, text `bun.lock`) with an alias and a `file:` dependency | `bun pm ls --all`, the alias read as its package, the `file:` package dropped |
| `deno-v3`, `deno-v4`, `deno-v5` | `deno cache` (Deno 1.46), `deno install` (Deno 2.0, Deno 2.5) with npm, peer-dependency and `jsr:` imports | `deno info --json`, `npmPackages` |
| `poetry-v1`, `poetry-v2` | `poetry lock` (Poetry 1.2 → lock-version 1.1, Poetry 2.5 → 2.1) with a path dependency and a dev group | `poetry export --with dev --without-hashes`, `==` pins |
| `pipenv` | `pipenv lock` (pipenv 2026.10) with an editable path package and dev packages | `pipenv requirements --dev`, `==` pins |
| `gem` | `bundle lock` (Bundler 4.0) with a `path:` gem and platform-specific nokogiri | Bundler's `LockfileParser`, specs from rubygems sources |
| `composer` | `composer update --no-install` (Composer 2.8) with a `path` repository and `require-dev` | `composer show --locked --format=json`, the path package dropped |
| `pub` | `dart pub get` (Dart 3.13) with a path package and a dev dependency | `dart pub deps --json`, hosted packages |
| `mix` | written by hand in Mix's format (no Hex repository reachable here): an aliased package, a git dependency, a private organization's package; checksums from the hex.pm API | by hand |
| `gradle` | `gradle dependencies --write-locks` (Gradle 8.14) | `gradle dependencies`, every coordinate listed |
| `maven` | written by hand (Maven has no lockfile): properties, `dependencyManagement`, a test scope, a plugin dependency | `mvn dependency:list -DexcludeTransitive` (Maven 3.9) |
| `nuget-v1`, `nuget-v2` | `dotnet restore` (.NET SDK 8.0) with `RestorePackagesWithLockFile`, a project reference; v2 with central package management and transitive pinning | `dotnet list package --include-transitive --format json` |
| `conan-v04`, `conan-v05` | `conan lock create` (Conan 1.66 with revisions, Conan 2.32) over locally exported recipes (ConanCenter isn't reachable here), a `tool_requires` and a `@user/channel` recipe | `conan info --json`, `conan graph info --format=json`, the `@user/channel` recipe dropped |

The npm, pnpm, Yarn, Bun and Deno cases share one dependency set (an alias, a scoped package,
nested versions, dev dependencies), and the uv, requirements, Poetry and Pipenv cases another,
so a format difference shows up as a diff, not a different resolution.

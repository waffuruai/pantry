# Pantry vs Canadian Centre for Cyber Security advisories

Audit date 2026-11-18. Pantry at `origin/dev` ebcbb43 (2026-11-17), plus Tom's 12 open PRs read from `refs/pull/N/head`. Advisories: the Cyber Centre's own JSON API, the 150 most recently created entries (2026-10-09 to 2026-11-17); the 90 days to 2026-11-18 hold 347, so the oldest 197 are not in this audit. Gaps are tracked in [#247](https://github.com/waffuruai/pantry/issues/247); the Cyber Centre as a source in [#248](https://github.com/waffuruai/pantry/issues/248). Of Tom's PRs, #226, #241 and #246 merged after this was written; the rest were still open.

## Summary

- **150 advisories**: 83 in scope (58 wholly, 25 mixed: an appliance or enterprise advisory with a desktop, library or OS part), 67 out of scope (appliances and firmware, ICS/OT, mobile, hardware, enterprise suites, one phishing alert).
- **In scope, on dev today**: 11 covered, 33 partial, 39 not covered.
- **Once the 12 PRs merge**: 12 covered, 32 partial, 39 not covered. The PRs mostly turn a warn into a named CVE or close one platform (Linux browsers, Java, PHP outside Homebrew, .NET runtimes, Windows programs by CVE record); only the Java alert crosses to fully covered, because the Windows legs of the browser and Microsoft advisories stay open.
- **Exploitation**: 22 advisories name a KEV CVE, 6 report exploitation that KEV does not list (CCCS citing the vendor or open-source reporting). In scope: 11 with KEV, 3 without.
- **Why partial is the common answer**: Pantry's machine inventory returns early on Windows (`checks/machine/mod.rs`, #11), browsers are only inventoried on macOS, and tools that Homebrew or a vendor's Linux repo installed are left to `brew vulns` or the distro check, which see nothing when OSV's git-tag lookups are empty: on 2026-11-18 they returned nothing for the PHP, Node.js, nginx and MongoDB versions just below these advisories' fixes, and nothing for httpd at any version tried. Linux packages from a vendor's own repo (MongoDB, nginx.org, HashiCorp, TeamViewer, GitLab) are treated as OS-owned, and distro OSV doesn't know them.
- **The 74 CVEs the advisories name** (45 advisories name any; 105 name none): OSV maps 19 to a package or repo Pantry queries, has 1 as a record only, and has no record for 54; 23 are in KEV; CVE.org has numeric affected versions for 64, versions it can't compare for 6, and 4 are not yet published there. Most of the 54 OSV misses are appliances; the in-scope ones are Telerik's 6, Microsoft's two exploited CVEs (Office, Windows) and Citrix's Secure Access Client pair, which CVE.org hasn't published yet.
- **Cyber Centre as a source**: worth adding as an exploitation and "national CERT published" signal plus product fix floors, not as a vulnerability database. See the section near the end.

### Coverage legend

- **covered**: inventoried on the platforms the product runs on, and its fixed version is compared (OSV, endoflife.date, a release feed, KEV or the vendor's latest). Where only the latest-version check catches it, the finding warns `OUTDATED` and names no CVE; the note says so.
- **partial**: some platforms, install methods or products in the advisory are checked and others aren't.
- **not**: in scope but nothing would flag an affected install.
- OSV column: `package` means an OSV record maps the CVE to an ecosystem or git repo Pantry queries (Debian/Ubuntu, Packagist, PyPI, Go, the catalog's repos); `record only` means OSV has it but only under something Pantry never asks; `no` means no OSV record (CVE id, DEBIAN-/UBUNTU- id or alias) was found.

## The Cyber Centre as a data source

### What it publishes

| | Atom feed | JSON API |
|---|---|---|
| URL | `https://cyber.gc.ca/api/cccs/rss/v1/get?feed=alerts_advisories&lang=en`, which 301s to `https://www.cyber.gc.ca/api/cccs/atom/v1/get?feed=alerts_advisories&lang=en` (Atom, not RSS); `lang=fr` for French | `https://www.cyber.gc.ca/api/cccs/threats/v1/get?lang=en&content_type=cccs_threat`: the site's own backend, which the listing page calls; undocumented |
| Size and depth | the 50 newest entries (about two weeks), 145 KB | every entry since 2018-06-08 (6,528), 19 MB in one response |
| Fields | `id`, `link`, `title`, `updated`, empty `summary`, full HTML `content` | `nid`, `uuid`, `title`, `serial_number` (AV26-1168, AL26-029), `alert_type` (396 advisory, 397 alert, 398 control systems), `subject` (a vendor tag, unreliable: Johnson Controls is tagged `juniper`, many are `other`), `date_created`, `date_modified`, `url`, `body` (HTML), `external_url`, `moderation_state` |
| Caching | no `ETag`, `Last-Modified` or `Cache-Control` on either, so no conditional GET; Pantry's "ask whether it changed" fetch would download the whole thing each time | same |

Nothing is structured beyond the envelope. The body has a fixed shape: serial number, date, "Updated" (latest only), "As of <date>, <vendor> is affected by vulnerabilities in the following products:" then product / "Prior to X" pairs, then exploitation sentences ("Google indicates that CVE-… is exploited in the wild", "Open-source reporting indicates…", "On <date>, CISA added CVE-… to their KEV Catalog") under "Update N" headings, then links to the vendor's bulletin. Alerts (AL) add affected/fixed tables and mitigations. There are no CVSS scores, CPEs or purls, product names are the vendor's prose, and version floors are text ("Prior to 19.5.6", "Versions 1.0.3 to versions prior to v1.0.10", "Multiple versions").

- **CVEs**: named in 45 of these 150 advisories (112 of the 347 in 90 days). Most advisories name products and fixed versions only and link to the vendor.
- **Exploitation**: stated in 28 of 150, citing the vendor, open-source reporting or KEV.
- **Cadence**: 347 entries in 90 days, about 5.4 per business day, weekdays (one Sunday post), usually the vendor's day or the next. 32 of the 347 were updated later, mostly to add an exploitation or KEV line; only the latest update date is kept, so when a flag appeared is only visible by polling.
- **Prior art**: Filigran's OpenCTI has a CCCS advisories connector, so others consume it.

### Licence and terms

- Neither the feed nor the API carries a licence. The site's footer links the Government of Canada's [Terms and conditions](https://www.canada.ca/en/transparency/terms.html) (modified 2025-09-05): non-commercial reproduction is allowed with due diligence on accuracy, the title and author, and a note that it is a copy of the version at the source URL; reproduction "for the purposes of commercial redistribution" needs prior written permission from the copyright administrator (for this content, the Communications Security Establishment).
- No Open Government Licence – Canada statement was found for alerts and advisories (some Cyber Centre publications are on open.canada.ca under it, but not this feed). The My Cyber Portal terms, seen only in a search snippet, say the Cyber Centre's name and graphics need CSE's permission.
- No `robots.txt` (404) and no published rate limits or API terms. Calling the undocumented JSON API automatically is unaddressed either way.
- For Pantry: a user's machine reading a public feed and storing only facts (advisory id, URL, date, CVE ids, product and fixed version, exploited yes/no) with a link back is close to the non-commercial reading the terms allow. Showing their text in reports, or feeding it to Syrup (sold), is commercial redistribution and needs written permission. Ask contact@cyber.gc.ca for permission, or for confirmation that OGL – Canada applies, before it ships on by default.

### What it has that OSV, KEV and CVE.org don't (this sample)

1. **Exploitation KEV doesn't list (6 CVEs, as of KEV 2026.11.17)**: CVE-2026-118539 Drupal Commerce and CVE-2026-123488 Craft CMS (both in scope), CVE-2026-125883 N-able N-central, CVE-2026-101767 Oracle E-Business Suite, CVE-2026-106173 FortiSIEM, CVE-2026-107441 Zyxel.
2. **Exploitation sooner than KEV**: CVE-2026-123039 (Check Point) by one day, from the vendor's statement. CVE-2026-116606 (Barracuda) and CVE-2026-111357 (Ivanti) were flagged in an update before KEV added them, but the update dates aren't kept, so the lead can't be measured (at most 8 and 17 days). Everywhere else the Cyber Centre relays KEV the same day or later (PHP: KEV 10-26, Cyber Centre 10-27).
3. **CVEs CVE.org hasn't published**: 4 (CVE-2026-102701 Xen, CVE-2026-115560 PHP, CVE-2026-118268 and -118269 Citrix Secure Access Client).
4. **Not a faster CVE source**: for the 70 published CVEs, the Cyber Centre's first mention is the same day as CVE.org for 46, 1-5 days later for 20 and 15 days later for 1. The 3 apparent leads are CVEs added to an older advisory in a later update.
5. **Fix floors for products OSV doesn't map**: GitLab, n8n, Node.js 22/24/26, MongoDB Server and drivers, Mattermost, Docker Desktop, TeamViewer, JetBrains, Atlassian, HashiCorp, Telerik. These are the vendors' own numbers restated, but in one place and one shape.
6. **Curation**: it chooses which bulletins to republish, and its alerts (AL, 11 in 90 days: here Java4Shell, Brotli, php2shell, BeyondTrust) single out the critical ones.

### Recommendation

Add it, as a signal source rather than a vulnerability database, opt-in until the Cyber Centre confirms the terms:

- **Exploited mark.** When the Cyber Centre says a CVE is exploited and KEV doesn't list it, mark the finding "exploited (Cyber Centre)" with the advisory link, and order it with KEV. In this sample that marks 2 in-scope findings Pantry already fails (Drupal Commerce), or would once OSV catches up (Craft CMS).
- **National-CERT mark.** Tag findings whose CVE is in an alert (AL), or whose installed version is below an advisory's floor: "Cyber Centre advisory AV26-1168".
- **Fallback floors.** For products Pantry inventories but OSV doesn't map (GitLab, n8n, Node.js, MongoDB, Docker Desktop, TeamViewer once inventoried), use the "Prior to X" floors through a hand-kept map from Cyber Centre product names to components. These should warn and never fail on their own, since they are parsed from prose.
- **Don't use it** for CVE discovery or version ranges (CVE.org and OSV come first and are structured) or for severity (it has none).
- **How**: read the Atom feed daily (145 KB covers two weeks), backfill once from the JSON API, keep only the derived fields, link every finding to the advisory. Ship it first as a third-party source users add to their own sources file, as Maltrail's trails is today, and make it default-on once written permission or OGL confirmation arrives.

## Method and what could not be verified

- **Advisories**: the Atom feed holds only 50 entries, so the list comes from the JSON API (`content_type=cccs_threat`), filtered to `moderation_state = published` and created since 2026-08-20 (347), newest 150 kept (AV26-1024, 2026-10-09, to AL26-029, 2026-11-17). Generic User-Agent; nothing about us sent. Products, versions, CVEs and exploitation lines were parsed from each body; exploitation is "yes" when the text says exploited or cites KEV ("not aware of active exploitation" excluded).
- **Pantry**: read from `origin/dev` (ebcbb43) without touching the checked-out branch; PRs from `refs/remotes/pr/N`. Files read: `checks/machine/{mod,catalog,tools,components,app_updates,apps,os_updates,os_packages,brew_vulns,cellar,editors,images,packages,linux/kernel}.rs`, `utils/files.rs` (`owner`), `utils/os.rs`, `sources/{releases,osv,distros}.rs`, `assets/defaults/sources.toml`, `docs/public/checks-and-sources.md`; PRs' `kev_catalog.rs`, `software_cves.rs`, `programs.rs` and descriptions. wpantry was not run; coverage is from the code.
- **OSV, KEV, CVE.org**: queried 2026-11-18 (OSV by CVE id, DEBIAN-/UBUNTU- id and aliases, plus package/version and git-tag queries for products without CVEs; KEV `cisagov/kev-data` 2026.11.17; CVE.org API). OSV adds records continuously, so the Node.js, nginx, MongoDB and Craft gaps may close upstream without a Pantry change.
- **Homebrew cask catalog**: downloaded to check which apps have an `app` artifact (first cask wins, as `releases::casks` does).

Not verified:

- What `brew vulns` (Homebrew's command) queries. Assumed OSV by each formula's source repo and version, the same tag lookups that came back empty; not run.
- #230's Windows behaviour (Tom didn't run it on Windows either) and whether Chrome, Firefox, TeamViewer and Siemens programs' registry names match their CVE records.
- Which CVEs sit behind the 105 advisories that name none: vendor bulletins weren't fetched, so the OSV/KEV/CVE.org columns cover only the 74 CVEs the Cyber Centre names.
- That Craft CMS's recent GHSAs at 5.10.0 match AV26-1067's fixes; the SAP SDK package names (guessed); Magento's records for AV26-1039's release.
- That nginx.org repo packages read clean against Debian's fixed versions (inferred from how dpkg versions compare, not tested).
- The licence: no OGL statement was found for the feed or API, and the My Cyber Portal terms were seen only in a search snippet.
- The other 197 advisories in the 90-day window.

# Lockfile golden files

Each directory holds one lockfile and `expected.txt`, the `ecosystem name version` lines its
extractor must return (sorted). The lockfiles were generated by the real tools, and each
`expected.txt` comes from that tool's own view of the result, not from our parser:

| Case | Lockfile made with | Expected from |
|---|---|---|
| `cargo-v4` | `cargo generate-lockfile` (registry, path and git dependencies) | `cargo metadata`, crates.io sources |
| `cargo-workspace` | this workspace's own `Cargo.lock` | `cargo metadata`, crates.io sources |
| `npm-v3`, `npm-v1` | `npm install --package-lock-only` (npm 10, `--lockfile-version 1` for v1) | `npm ls --all --json` |
| `pnpm-v9`, `pnpm-v6` | `pnpm install --lockfile-only` (pnpm 10, pnpm 8) | `pnpm list --depth Infinity --json` |
| `go` | `go mod tidy` (Go 1.24) with `replace` and `toolchain` directives | `go mod edit -json`, replaces applied, `toolchain` as `stdlib` |
| `uv` | `uv lock` (uv 0.11) with an editable project | `uv export --all-groups --no-emit-project` |
| `swift-v1`, `swift-v2` | written by hand in SwiftPM's formats (no Swift toolchain here) | by hand |

The npm, pnpm, uv and Cargo cases share one dependency set (an alias, a scoped package,
nested versions, dev dependencies) so a format difference shows up as a diff, not a
different resolution.
